# 保持登录：完整开发学习与验收

2026-10-18。本课在 `feat/persistent-login` 上接续前两课，完成本地代码与自动化测试；尚未提交、发布或完成真实浏览器人工验收。服务器不因本地代码变更自动更新。

## 一、这次做的完整功能

目标：登录后刷新或重新打开页面，在固定 7 天有效期内恢复身份；退出撤销当前会话，旧凭证立即失效。访问不会延长有效期。注册密码仍为 7～128 位，与会话有效期无关。

三种东西要分清：

| 保存在哪里 | 保存什么 | 作用 |
| --- | --- | --- |
| SQLite 的 login_sessions | token 哈希、用户 ID、到期时间、撤销时间 | 后端决定凭证是否有效 |
| 浏览器 HttpOnly Cookie | 随机会话 token | 浏览器保存并自动携带凭证，页面 JS 不能直接读取 |
| Vue 内存 | 当前用户信息、恢复状态 | 展示用户名、等待恢复、决定页面跳转 |

账单本身此前已经持久化。这里解决的是身份恢复，不是重新保存账单，也不是保存用户密码。

## 二、按完整请求流程阅读代码

### 1. 登录：密码验证通过，再发放 Cookie

阅读 `routers/auth.py` 的 `authenticate_password`、`browser_login`，再读 `browser_session.py`。

前端提交 `POST /api/auth/browser/login`，代理去掉 `/api` 后交给后端。后端验证 CSRF 防护头、来源、登录频率和密码，撤销该浏览器原会话，生成新会话并提交数据库。

响应 JSON 只有用户 ID 和用户名；`Set-Cookie` 下发随机凭证。前端无需读取该响应头，也不保存 access_token。

Cookie 设置：

- `HttpOnly`：页面 JavaScript 不能直接读取 Cookie；它不能防住所有 XSS。
- `Max-Age=604800`：保存 7 天，支持关闭后重新打开浏览器。用户主动清除 Cookie、隐私模式或浏览器策略仍可能提前删除。
- `SameSite=Lax`：减少跨站携带 Cookie 的场景，作为额外防护。
- `Secure`：HTTPS 环境开启；本地 HTTP 开发显式关闭。
- `Path=/`：同时适用于浏览器 `/api` 代理路径与应用页面；不指定 Domain。

原 `/auth/login` 仍服务于 Swagger、脚本和已有 Bearer 客户端，它也使用同一张会话表和同一个限流器。浏览器使用专门接口避免把会话凭证暴露到响应 JSON。这不是同时使用 JWT 和数据库两套鉴权：新凭证统一查数据库，旧 JWT 不再有效。

### 2. 请求：自动携带 Cookie，服务端查会话

阅读 `frontend/src/api/client.ts` 与 `dependencies.py`。

前端请求固定走同源 `/api`，`credentials: 'same-origin'` 让浏览器附带 Cookie。服务端通过 `get_active_session()` 检查是否存在、过期、撤销，再查用户。

显式携带 Authorization 时优先验证它。错误的 Authorization 直接拒绝，不会用有效 Cookie 悄悄兜底。

### 3. CSRF：为什么有 Cookie 之后还要加一道检查

浏览器会自动带 Cookie，其他网站也可能诱导浏览器发送请求。所以“带了 Cookie”本身不能证明修改请求来自我们的页面。

本项目是同源 Vue + JSON API，采用自定义请求头方案：

1. 前端为 POST、PATCH、DELETE 等请求加 `X-CSRF-Protection: 1`。
2. 浏览器登录、退出，以及用 Cookie 鉴权的修改操作，都必须带这个头。
3. 若带 Origin，必须与 `BROWSER_ORIGINS` 中一个完整地址精确匹配；明确的 cross-site 请求拒绝。
4. 后端不开放跨域 CORS。跨域脚本添加自定义头会先发预检，不能得到允许；普通跨站表单又无法设置这个头。

这里的 `1` 不是秘密，也不是随机 CSRF token。安全性来自浏览器同源限制、自定义头与严格来源策略。缺少 Origin 时仍要求自定义头。将来如果要开放 CORS，必须一起重新审查这项策略，不能允许任意来源携带凭证。

GET 请求只读取，不修改数据。手动 Bearer 客户端的凭证不会由浏览器自动附加，因此仍可使用原脚本调用方式。

### 4. 刷新：先恢复身份，再决定页面

阅读 `frontend/src/auth.ts` 的 `restoreSession()`，然后读 `router/index.ts` 和 `App.vue`。

```text
打开 /statistics/yearly
  → 显示“正在恢复登录状态”
  → GET /api/auth/me（浏览器自动带 Cookie）
      200：保存用户信息，展示原来的年度统计页
      401：确认没有有效会话，跳转登录页
      网络故障/5xx：保留目标地址，隐藏业务页面，显示重新连接
```

多个导航共用同一次恢复请求，避免重复调用。`authReady=false` 表示尚未确认身份，不等于已经退出。

`revision` 是前端请求版本号：退出或重新登录时递增。旧请求回来时检查版本，避免旧 401 清掉新登录，或旧数据覆盖退出后的页面。它不是服务端身份凭证。

### 5. 退出：先让服务端撤销，再清页面

阅读 `auth.ts` 的 `logout()`、`App.vue` 的退出交互，以及后端 `browser_logout()`。

前端 POST → 后端撤销当前 Cookie 对应的会话并提交 → 清除同名同路径 Cookie → 返回 204 → Vue 清用户状态并跳登录。

会话已过期、Cookie 已不存在、重复点击退出，浏览器退出接口都允许成功清理。退出时网络故障会显示“退出未确认”，允许重试；页面不会宣称已退出。即使第一次请求已在服务端执行而响应丢失，重试也能成功。

退出仅影响当前会话，不会撤销其他浏览器或设备独立登录的会话。同一浏览器多个标签共享 Cookie：其他标签下一次请求会发现会话失效；本版没有做即时跨标签 UI 广播。

## 三、本地如何运行

已有本地数据库已迁移到 `75b8e310dd96`。本课没有再增加数据库字段。

在原 `(sc)` PowerShell、项目根目录启动后端。以下环境变量仅作用于当前终端及其启动的进程，不修改真实 `.env`，也不需要展示密钥：

```powershell
cd E:\111\expense-tracker
$env:SESSION_COOKIE_SECURE = 'false'
$env:BROWSER_ORIGINS = '["http://localhost:5173","http://127.0.0.1:5173"]'
python -m alembic current
python -m uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

如果原后端正在运行，先在其终端 Ctrl+C，再按上面方式启动。避免两个进程抢占同一端口。

另开一个终端启动前端：

```powershell
cd E:\111\expense-tracker\frontend
npm.cmd run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

访问 `http://127.0.0.1:5173`。不要在 localhost 和 127.0.0.1 之间来回切换，它们的 Cookie 不共享。若自行换端口，必须同步修改 BROWSER_ORIGINS；那里写浏览器看到的地址，不是内部 API 端口。

## 四、亲手验收：一轮完整用户操作

| 操作 | 预期 |
| --- | --- |
| 正常登录 | 进入账单页，显示用户名 |
| 打开年度统计，再刷新 | 恢复后仍在年度统计，不误跳登录 |
| 关闭标签，重新输入年度统计地址 | 有效期内恢复身份 |
| 开发者工具 Application → Cookies | expense_session 有 HttpOnly、SameSite、到期时间；HTTP 本地 Secure 关闭 |
| 新增、修改、删除一笔测试账单 | 正常成功，金额与统计仍正确 |
| 后端停止，再刷新页面 | 显示暂时无法确认登录状态和重新连接 |
| 重启后端，点击重新连接 | 恢复原页面；会话保存在 SQLite，不因后端重启丢失 |
| 后端停止，点击退出 | 显示退出未确认，恢复后端后可重试 |
| 正常退出，再刷新或重新打开 | 要求登录 |
| 同浏览器开两个标签，在一个退出 | 另一个下一次受保护请求返回未登录 |

CSRF 可在登录状态下的浏览器控制台执行这条只用于测试的请求：

```javascript
await fetch('/api/auth/browser/logout', {
  method: 'POST', credentials: 'same-origin'
}).then(r => r.status)
```

预期 403，因为没有自定义防护头；随后刷新仍保持登录。不要把 Cookie 的值复制发给别人。固定 7 天到期和旧凭证重放已由测试推进模拟时钟验收，不需要修改电脑时间或等待一周。
