## 当前链路

浏览器 127.0.0.1:18080 → SSH 隧道 → 服务器 127.0.0.1:8080 → web 容器 Nginx。

Nginx 提供 Vue 静态文件；/api/ 前缀剥离后转发给 api:8000。页面路由回退到 index.html，API 错误保留后端响应。所有组件均运行在服务器，浏览器访问的是服务器数据。

## 启动与检查

以下在服务器执行，前提是后端已运行、前端镜像已导入：

```bash
cd /opt/expense-tracker
docker compose -f compose.yaml -f compose.web.yaml config --quiet
docker compose -f compose.yaml -f compose.web.yaml up -d --no-deps --no-build --pull never web
docker compose -f compose.yaml -f compose.web.yaml ps
docker compose -f compose.yaml -f compose.web.yaml exec web nginx -t
curl --fail --show-error http://127.0.0.1:8080/api/health
curl -i http://127.0.0.1:8080/api/not-found
docker compose -f compose.yaml -f compose.web.yaml logs --tail=50 web
```

健康接口预期 200 JSON；不存在的 API 预期 404 JSON，不能返回前端 HTML。config 使用 --quiet，避免输出展开后的环境变量。

Windows 新开终端建立隧道，保持该终端运行：

```powershell
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:18080:127.0.0.1:8080 -i "$env:USERPROFILE\.ssh\expense-tracker-deploy" root@47.101.55.88
```

浏览器访问 http://127.0.0.1:18080。当前无需开放公网 8080；刷新需重新登录是内存 Token 的设计。

## 下次更新前端

1. 源码和配置提交 Git，测试与构建通过，记录源码提交；工作区应干净。
2. 使用新镜像版本，例如 1.0.1，不覆盖本次 1.0.0。
3. 导出、上传并校验 tar，服务器加载镜像；保留旧镜像和旧配置副本。
4. 将服务器 compose.web.yaml 中 web.image 改为新版本；同步提交仓库配置，避免长期漂移。
5. 运行上面的 config 检查和仅更新 web 的 up 命令，再完成健康与页面业务检查。

前端发布通常不需要重建后端或重建数据卷。后端若另行重建、容器 IP 变化，当前 Nginx 配置需要重启 web 重新解析 api 地址：

```bash
docker compose -f compose.yaml -f compose.web.yaml restart web
```

## 前端回退

本次是前端首次部署，没有更早的已验收前端版本。1.0.0 作为后续回退基线保留。

未来 1.0.1 更新失败时，先确认旧镜像仍存在：

```bash
docker image inspect expense-tracker-web:1.0.0 --format '{{.Id}}'
```

把 compose.web.yaml 的 web.image 恢复为 expense-tracker-web:1.0.0，并恢复与旧版本匹配的配置，再执行 config 检查和仅更新 web 的 up 命令，重新验收。此操作会短暂中断前端，不是零停机发布。

如果只是要关闭本次首次部署的前端：

```bash
docker compose -f compose.yaml -f compose.web.yaml stop web
```

不执行 down -v、不删除后端数据卷。前端回退不会撤销已经写入的账单，数据恢复是另一个流程。本次记录的是可执行回退步骤，尚未声称做过回退演练。
