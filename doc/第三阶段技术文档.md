# 个人记账后端：第三阶段技术文档

阶段目标：计算指定月份的总收入、总支出和收支结余，并通过已知账单核对结果。

阶段状态：已完成。依据为当前 main.py 统计代码核对，以及学习者确认月度收入支出功能测试正常的反馈。本次文档整理未重新执行 HTTP 请求或自动化测试，未改动业务代码和账单数据。

## 1. 接口约定

```http
GET /statistics/monthly?month=2025-02
```

month 必填，格式为 YYYY-MM，月份范围 01～12，当前允许年份为 0001～9998。缺少参数、月份格式错误或年份超出范围均返回 422。

成功状态码为 200，响应示例：

```json
{
  "month": "2025-02",
  "income_cents": 100000,
  "expense_cents": 23000,
  "balance_cents": 77000
}
```

| 字段 | 含义 |
| --- | --- |
| month | 被统计的月份 |
| income_cents | 月度收入总额，单位为分 |
| expense_cents | 月度支出总额，单位为分 |
| balance_cents | 收入减支出，单位为分，可以为负数 |

balance_cents 表示本月收支差额，不是银行卡余额，也不包含上月结余。无账单月份返回 200，三个金额均为 0。

## 2. 月份范围

沿用第二阶段的日期范围算法：

```text
2025-02 → occurred_on >= 2025-02-01
          occurred_on <  2025-03-01
```

包含月初、不包含下月月初，避免手工计算每月天数。十二月的结束日期为下一年一月一日。

统计依据是 occurred_on（实际收支日期），不是 created_at（录入时间）。例如今天补记二月的账单，仍计入二月。

当前列表接口和统计接口各自保留一份月份范围计算代码，尚未提取共用函数。

## 3. 聚合查询的实现

新增导入：

```python
from sqlalchemy import select, func
```

核心查询：

```python
statement = (
    select(
        Transaction.kind,
        func.sum(Transaction.amount_cents),
    )
    .where(
        Transaction.occurred_on >= start_date,
        Transaction.occurred_on < end_date,
    )
    .group_by(Transaction.kind)
)

with Session(engine) as session:
    rows = session.execute(statement).all()
```

逻辑上对应：

```sql
SELECT kind, SUM(amount_cents)
FROM transactions
WHERE occurred_on >= :start_date
  AND occurred_on < :end_date
GROUP BY kind;
```

参数通过 SQLAlchemy 绑定，不是自行拼接用户输入。SUM 在数据库内求和，GROUP BY 将收入和支出分别分组。

本查询没有 limit 或 offset，因此统计覆盖月份范围内全部记录，不受列表分页影响。也没有分类筛选，统计该月全部分类。

## 4. execute 与 scalars 的区别

列表查询选择 Transaction 模型对象，使用 scalars 可以直接取得对象。统计查询选择两列：类型和总金额，因此使用 execute 保留完整行。

示例结果：

```python
[
    ("expense", 23000),
    ("income", 100000),
]
```

不能在这里使用 scalars 获取两列数据，因为它默认仅提取每行第一列。分组结果的顺序不作保证，代码通过类型名称填入 totals，而不依赖顺序。

## 5. 缺失类别与空月份

```python
totals = {"income": 0, "expense": 0}

for kind, total in rows:
    totals[kind] = total
```

只有支出的月份不会产生 income 分组，默认值保留为 0；完全无记录时 rows 为空，收入和支出都为 0。

最终计算：

```python
income = totals["income"]
expense = totals["expense"]
balance = income - expense
```

当前收入和支出类型由已有创建、修改输入模型约束。统计为实时查询结果，没有缓存、额外汇总表或历史快照，提交修改或删除后，下次统计会反映新的数据。

## 7. 日期校验排查记录

学习者曾观察到“二月三十日似乎可以创建，但未被计入统计”。进一步确认是看错响应行，实际 POST 返回 422，没有入库，不是统计遗漏。

当前创建输入模型声明 occurred_on: date，Pydantic 会校验真实日期；修改模型也使用 date 类型。示例：

| 日期 | 合法性 |
| --- | --- |
| 2025-02-28 | 合法 |
| 2025-02-29 | 非法，2025 年不是闰年 |
| 2024-02-29 | 合法 |
| 2025-02-30 | 非法 |

前端输入框能填写文字不等于创建成功。判断结果应查看 POST 的响应状态码和响应内容：201 表示成功创建；422 表示校验失败，不进入写入逻辑。

后端必须负责数据合法性，前端日期选择器只是交互辅助，不能替代后端校验。还需区分真实日期合法性与业务限制：当前没有禁止未来日期；统计年份上限为 9998，而输入 date 的日期范围更宽，后续可统一日期范围约定。
