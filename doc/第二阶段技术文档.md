## 2. 删除账单与事务提交

执行步骤：

1. 使用 session.get(Transaction, id) 按主键查询。
2. 不存在时抛出 HTTPException，返回 404 和“账单不存在”。
3. session.delete(transaction) 标记待删除对象。
4. session.commit() 执行并提交删除。
5. 返回 Response(status_code=204)，不包含 JSON 响应体。

这是物理删除，数据库记录被移除，目前没有回收站或恢复接口。

### 学习实验：省略 commit 会发生什么

学习者已验证：接口仍能返回 204，但再次查询仍能查到账单。

原因是 HTTP 状态码由代码决定，并不会自动检查数据库操作是否提交。Session 退出时不会自动提交未提交的删除；成功提交之后，才应返回成功响应。当前代码已经保留 commit。

重复删除同一个已不存在的编号返回 404。这个接口没有要求重复操作返回相同状态码。

## 3. PATCH 部分更新

示例请求：

```http
PATCH /transactions/1
Content-Type: application/json
```

```json
{"amount_cents": 1500}
```

只更新金额，其他字段保持原值。TransactionUpdate 中允许出现的字段为 kind、amount_cents、category、occurred_on、note；id 和 created_at 不属于可修改字段。

| 输入情况 | 行为 |
| --- | --- |
| 未提交某字段 | 保留该字段原值 |
| note 为 "" | 清空备注，保存为空字符串 |
| 任一已提交字段为 null | 422，修改字段不能为 null |
| 空对象 {} | 422，请至少提交一个要修改的字段 |
| 金额非正数等非法值 | 422，参数校验失败 |
| 合法请求但账单不存在 | 404，账单不存在 |

### 核心实现

```python
changes = body.model_dump(exclude_unset=True)
```

exclude_unset=True 只提取客户端实际提交的字段，避免将未提交字段的默认 None 写入数据库。显式提交的 null 仍会出现在 changes 中，因此随后进行拒绝空值的检查。

```python
for field, value in changes.items():
    setattr(transaction, field, value)

session.commit()
session.refresh(transaction)
```

setattr 根据字段名设置对象属性。对象从当前 Session 中查出，SQLAlchemy 会跟踪它的改动，提交时执行更新，无需再次 add。refresh 重新读取记录后，代码构造并返回账单字典。

当前模型沿用 Pydantic 默认的额外字段忽略行为：提交未知字段不会修改对象；如果仅提交未知字段，changes 为空，返回 422。输入模型允许 None，但业务代码拒绝显式 null，自动文档对可空性的描述与实际接口限制仍有改进空间。

## 4. 列表与分页

示例：`GET /transactions?offset=0&limit=10`。

| 参数 | 默认值 | 校验 | 含义 |
| --- | --- | --- | --- |
| offset | 0 | 整数且大于等于 0 | 跳过的记录数 |
| limit | 10 | 整数，范围 1～100 | 最多返回的记录数 |

每页十条时，第 1 页 offset=0，第 2 页 offset=10，第 3 页 offset=20。

```python
statement = (
    select(Transaction)
    .order_by(Transaction.id.desc())
    .offset(offset)
    .limit(limit)
)
transactions = session.scalars(statement).all()
```

select 构造查询，scalars(...).all() 执行查询并取得模型对象列表。分页由数据库执行，不是读取全部记录后在 Python 中切片。

使用唯一 ID 降序保证数据不变时的确定排序；这并不是按收支日期排序。跨页查询期间若新增或删除数据，offset 分页仍可能出现重复或跳过记录。

当前响应为数组，没有 total、总页数等元数据。没有匹配记录或 offset 超出范围时，返回 200 和 []。

## 5. 分类和月份筛选

示例：`GET /transactions?category=餐饮&month=2026-10&offset=0&limit=10`。

### 分类

category 可省略。传入时只能为餐饮、交通、购物、工资、其他之一；非法分类返回 422。

```python
statement = statement.where(Transaction.category == category)
```

### 月份

month 可省略。传入时格式为 YYYY-MM，月份必须为两位且在 01～12 之间；当前接口年份限定为 0001～9998，以便计算下个月第一天。

十月份转换为范围：

```text
occurred_on >= 2026-10-01
occurred_on <  2026-11-01
```

包含月初，不包含下月月初。十二月份的结束日期为下一年 1 月 1 日。筛选使用 occurred_on（实际收支日期），不使用 created_at（录入时间）。

分类和月份条件同时传入时必须同时满足。查询的逻辑顺序为：

```text
筛选 → 按 ID 降序 → 跳过 offset 条 → 取最多 limit 条 → 返回数组
```

分页作用于筛选结果。月份与分类均不传时，返回全部账单中的当前页。

### 删除

创建一条备注为“删除测试”的账单，记录 ID。先查询成功，再删除得到 204，随后查询和重复删除均为 404；重启后仍查不到。验证期间不创建新账单，以免当前 SQLite 编号生成方式复用已删除的编号，干扰观察。

### 修改

| 请求体 | 预期 |
| --- | --- |
| {"amount_cents":1500} | 只修改金额 |
| {"note":""} | 清空备注 |
| {"amount_cents":-1} | 422，原金额不变 |
| {"note":null} | 422 |
| {} | 422 |

合法输入修改不存在的编号返回 404。重启后修改结果仍保留。学习者明确确认了未提交字段不会更新。

### 分页

至少创建三笔账单。在数据不变时分别请求 offset=0&limit=2、offset=2&limit=2，检查顺序及无重复。offset=-1、limit=0、limit=101 返回 422；超出记录范围返回 []。

### 筛选边界

| 标记 | 分类 | 日期 |
| --- | --- | --- |
| A | 餐饮 | 2026-09-30 |
| B | 餐饮 | 2026-10-01 |
| C | 交通 | 2026-10-31 |
| D | 餐饮 | 2026-11-01 |

在上述四条记录中，month=2026-10 应包含 B、C；再增加 category=餐饮 时只包含 B。数据库中其他符合条件的记录也会返回，测试时应确保分页未遮蔽目标记录。

month=2026-13、2026-1、0000-01、9999-01 应返回 422；无账单月份返回 200 和 []。还可补测十二月跨年范围以验证年份切换。
