# 自动备份学习与验收方案

状态：2026-10-13 根据学习者最新决定暂缓。本文仅保留教学方案，尚未安装定时任务、配置异地存储或发送通知。存储目的地与通知渠道待学习者选择。已有手动备份、Windows 副本及隔离恢复流程；手动恢复反馈已归档至《服务器手动备份恢复验收记录》，备份文件名已提供；账单数量、Alembic 版本及恢复耗时仍需补齐。

## 目标与建议默认值

为即将开放使用的记账系统建立可检查的备份链路：数据库一致快照 → 校验 → 异地上传与校验 → 成功记录 → 到期清理；任一步失败保留错误并通知。

- 建议每 6 小时执行一次，按北京时间 00:15、06:15、12:15、18:15；发布和迁移前另做一次备份。
- 在任务持续成功、异地副本有效的前提下，数据恢复点目标约 6 小时；任务连续失败会延长数据丢失窗口。
- 服务器本地成功备份建议保留 7 天；异地成功备份建议保留 30 天。上线后按数据量和需求调整。
- 先列出过期候选文件验收，再启用自动删除；不按泛化的 *.db 搜索整个服务器。
- 本地到期备份只有在对应异地副本已经校验后才允许清理，并至少保留最近成功副本。失败任务不得执行清理。
- 远端保留策略仅作用于专用备份前缀；不使用会将本地删除同步到远端的镜像同步方式。
- 每月及数据库迁移后做隔离恢复，从异地下载副本进行验证，记录实际耗时。

上述时间与期限是本项目第一版建议，不是已经配置或已经达成的保证。

## 四步实施

### 1. 一键备份任务

复用 backup_db.py 与 verify_backup.py，新增服务器包装脚本；固定工作目录、设置文件权限、互斥锁和执行超时。不要依赖交互终端里的 restore_name、backup_path 等临时变量。

每次独立生成任务 ID 和目录，使用临时后缀写入，成功校验后再标为有效备份。记录 UTC 时间、文件名、文件大小、SHA256、用户/账单数量、真实 Alembic 版本、当前运行后端镜像 ID 和可用的源码标签。

现有备份脚本在生产数据卷 /data/backups 中生成快照。自动化必须同时管理这处暂存文件：确认宿主机导出和校验成功后，才清理本任务的容器内快照；若流程失败则保留并告警，不能让此目录无限增长。禁止触碰 /data/expenses.db。

### 2. 自动异地副本

选择独立存储服务。阿里云 OSS 私有桶是候选，其他对象存储或第二台服务器也可；仅在同一服务器增加目录不属于异地副本。若需覆盖地域级故障，选择另一个地域，并考虑传输成本。

备份使用唯一对象名，上传数据库及清单；失败重试有次数上限。上传后从远端读取并比对 SHA256，至少在验收阶段验证完整下载；对象存在并不等于校验通过。

凭证只在服务器配置文件或云实例身份中提供，限制到专用桶/前缀，禁止提交 Git 或粘贴到对话。配置私有访问和传输加密；远端删除权限与上传权限按实际存储能力分开。

异地保存数据库不代表已保存全部恢复条件。另行妥善保存部署配置、可获取的镜像和受保护的必要密钥；不要把真实 .env 混入普通 Git 文档。

### 3. 定时与失败通知

使用 systemd oneshot service + timer，指定时区，配置超时，保存 journal 日志；Persistent=true 用于错过计划执行后补触发一次，不会补出停机期间每个时刻的历史快照。

service 调用备份脚本；脚本非零退出视为失败。根据选择的邮件或机器人接入真实通知，通知只包含任务时间、阶段和摘要，不发送数据库、密码或密钥。

成功心跳仅在异地校验完成后更新；超过 8 小时无成功记录作为异常阈值。服务器关机或断网时本机通知也可能失效，因此完整方案需要服务器之外检查成功记录/心跳，不能只靠本机失败钩子。

### 4. 验收后启用清理

- 手动运行完整任务：本地快照、校验、异地对象与成功记录一致。
- 在测试目录/前缀模拟上传失败：任务非零退出、通知实际送达、不误报成功、不清理旧副本。
- 使用测试文件验证保留期边界、最新副本保护及目录范围。
- 安装 timer 后确认下次执行时间，观察一次真实定时执行。
- 从异地副本恢复隔离容器：登录、账单、统计与读写正确，正式数据库不受影响。
- 验证心跳过期提醒；分别区分任务失败与任务根本没有运行。

以上完成前，只能称为正在建设的备份流程，不能标记自动异地备份与通知已验收。

## 本地与服务器版本

本地开发分支可以领先服务器。普通界面改动不要求立即部署；已知安全修复和严重数据问题需优先安排发布。运维脚本独立部署和记录版本，不必同时重建前后端镜像。

镜像标签、Git 提交、数据库迁移版本是不同概念：

- expense-tracker-web:1.0.0：前端镜像标签。
- expense-tracker:1.0.0：后端镜像标签，与前端独立升版。
- Git 提交：源码身份，镜像可通过 revision 标签关联。
- Alembic revision：数据库结构版本，应从 alembic_version 或迁移命令读取；不是镜像的 1.0.0。

发布新内容时使用新镜像标签，并记录实际镜像 ID；不覆盖已发布的 1.0.0。修复可用 1.0.1，兼容新增功能或较大改进可用 1.1.0，不兼容变更采用新的主版本号。版本语义是约定，不能靠标签判断实际内容。

本次先完成备份闭环，再单独发布当前界面更新；仅前端变化时后端仍可保留已部署版本。拉取 Git、修改 Compose 标签都不会单独替换正在运行的容器，需加载相应镜像并执行受控更新。
