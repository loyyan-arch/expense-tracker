# 个人记账后端：第一阶段技术文档

整理日期：2026-10-09  
阶段目标：通过接口创建账单、按 ID 查询账单，并保证服务重启后数据仍然存在。  
阶段状态：已完成。依据为当前源代码、建表日志和学习者反馈的手工验收结果；本次整理未重新运行接口测试。

## 1. 已实现的功能与边界

- 创建一笔收入或支出，校验金额、分类、日期等输入。
- 根据账单 ID 查询记录。
- 记录不存在时返回 404，输入不合法时返回 422。
- 将账单保存到 SQLite 数据库文件中。
- 由数据库生成账单 ID 和创建时间。

目前用于本地学习。尚未实现登录、用户归属、列表、修改、删除、月度统计及公网部署，不应视为已经完成整个可上线项目。

## 3. 从 Python 函数到 HTTP 接口

一次查询的执行过程：

```text
浏览器发送 GET /transactions/2
    → Uvicorn 接收请求
    → FastAPI 匹配 /transactions/{id}
    → 将路径参数解析为整数 id=2
    → get_transaction() 查询数据库
    → 将结果转换成 JSON 返回
```

路由由请求方法和路径共同确定。GET /transactions/{id} 用于读取，POST /transactions 用于创建。浏览器地址栏直接访问发送的是 GET 请求，创建操作使用 /docs 发起 POST。

静态路径 /transactions/2 中的数字只是路径文本，不会自动改变返回字典中的 id。使用动态路径和同名函数参数后，编号才会进入函数：

```python
@app.get("/transactions/{id}")
def get_transaction(id: int):
    ...
```

访问 /transactions/abc 时，整数参数校验失败，返回 422。整数编号合法但记录不存在时，由业务代码返回 404。

## 4. 接口约定

### 4.1 首页

`GET /`

成功状态码：200。

```json
{"message": "欢迎使用个人记账 API"}
```

### 4.2 创建账单

`POST /transactions`

请求体示例：

```json
{
  "kind": "expense",
  "amount_cents": 1800,
  "category": "餐饮",
  "occurred_on": "2026-10-09",
  "note": "早餐"
}
```

| 字段 | 输入要求 |
| --- | --- |
| kind | 必填，只能是 income 或 expense |
| amount_cents | 必填，严格整数且大于 0，单位为分 |
| category | 必填，只能是餐饮、交通、购物、工资、其他 |
| occurred_on | 必填，能通过 Pydantic 日期解析；客户端使用 YYYY-MM-DD 格式 |
| note | 可省略，默认空字符串，最多 200 个字符 |

id、created_at 由服务端生成，不属于创建输入模型。当前模型没有配置拒绝额外字段，客户端应按上述字段提交。

成功状态码：201。返回示例，ID 和创建时间以实际响应为准：

```json
{
  "id": 1,
  "kind": "expense",
  "amount_cents": 1800,
  "category": "餐饮",
  "occurred_on": "2026-10-09",
  "note": "早餐",
  "created_at": "2026-10-09T08:50:00"
}
```

负数金额、非法分类、不可解析的日期等输入返回 422，业务函数不会执行。当前分类不与收入或支出类型绑定，例如尚未禁止 expense 搭配工资。

### 4.3 查询账单

`GET /transactions/{id}`

- 存在：200，返回与创建接口相同的账单字段。
- 不存在：404，返回 `{"detail": "账单不存在"}`。
- ID 不能解析为整数：422，由框架返回参数错误详情。

当前两个业务接口手工构造响应字典，尚未定义统一的 Pydantic 响应模型。

## 5. 数据库设计

表名：transactions。

| 字段 | SQLite 建表类型 | 约束或默认值 | 含义 |
| --- | --- | --- | --- |
| id | INTEGER | 主键、非空，插入时生成整数编号 | 唯一编号 |
| kind | VARCHAR | 非空 | income 或 expense |
| amount_cents | INTEGER | 非空，CHECK(amount_cents > 0) | 金额，单位为分 |
| category | VARCHAR | 非空 | 分类 |
| occurred_on | DATE | 非空 | 实际收支日期 |
| note | VARCHAR | 非空，SQLAlchemy 插入默认值为空字符串 | 备注 |
| created_at | DATETIME | 非空，数据库默认 CURRENT_TIMESTAMP | 记录创建时间 |

金额使用整数分，避免浮点运算精度问题。金额始终为正，收支方向由 kind 区分。

created_at 当前使用 SQLite 的 UTC 时间，读出的 datetime 不带时区标记；不要将其直接理解为北京时间。后续应统一 API 的时区表达约定。

输入校验与数据库约束不同：金额正数有双重保护；分类枚举、kind 枚举、备注最大长度目前仅在 Pydantic 输入层校验，数据库中尚无对应 CHECK 约束。

### 两个模型的区别

| 类 | 所在文件 | 职责 |
| --- | --- | --- |
| TransactionCreate | main.py | 描述客户端创建请求，解析并校验数据 |
| Transaction | models.py | 描述数据库表结构及账单对象 |

`body.model_dump()` 把输入对象转换为 Python 字典，日期字段此时已经是 Python date 对象；`Transaction(**body.model_dump())` 再用这些字段创建数据库模型对象。

## 6. 数据库连接与建表

db.py 使用以下路径定位数据库：

```python
DB_PATH = Path(__file__).resolve().parent / "expenses.db"
```

因此数据库文件固定在 db.py 同级目录，不会随启动时的工作目录改变。

engine 管理数据库连接；Base 是模型共用的基类，保存表结构元数据；echo=True 会打印执行的 SQL，便于学习。

init_db.py 导入 Transaction 后执行：

```python
Base.metadata.create_all(engine)
```

导入模型会将其表结构登记到元数据中。create_all 创建不存在的表，重复运行不会清空已有表，但不会自动修改已有字段。后续表结构变更需要引入迁移工具。

建表日志中 CREATE TABLE 表示执行建表，COMMIT 表示提交。随后查询表名产生的 ROLLBACK 是只读事务结束时的清理，不会撤销此前已提交的建表操作。

## 7. 创建与查询的数据库流程

### 创建

```python
with Session(engine) as session:
    transaction = Transaction(**body.model_dump())
    session.add(transaction)
    session.commit()
    session.refresh(transaction)
```

1. 创建本次操作使用的 Session。
2. 构造账单对象，add 将其加入会话。
3. commit 执行待写入操作并提交事务，完成持久保存。
4. refresh 从数据库重新读取，获取生成的 ID、创建时间等值。
5. 在会话内读取字段，构造响应字典。
6. 离开 with 块后关闭会话、释放资源。

add 本身不等于持久保存。当前也没有全局共用 Session，每次请求创建自己的会话。

### 查询

```python
with Session(engine) as session:
    transaction = session.get(Transaction, id)
    if transaction is None:
        raise HTTPException(status_code=404, detail="账单不存在")
```

session.get 按主键查找记录，查不到返回 None。HTTPException 会终止本次请求的正常处理并生成错误响应，不会停止整个服务。

## 10. 学习中遇到的问题

### 访问首页返回 404

最初没有注册 GET / 路由，访问根路径自然返回 404。后来添加 home 函数解决。此类错误表示路由未匹配，不代表服务未启动。

### 路径改成 /transactions/2 后仍返回 id=1

当时路径和响应都写死，两者没有自动关联。后续使用 /transactions/{id} 和同名函数参数，再按编号查询数据。

### 查不到账单却返回 null

内存版误写了 `if transactions is None`，检查的是整个字典。正确条件为 `if transaction is None`，检查单次查询结果。直接返回 Python None 会序列化成 JSON null，并不会自动产生 404。

### 为什么先用 SQLite

SQLite 减少数据库服务安装、账号和网络配置，方便先掌握读写、建模及事务。后续可迁移到 MySQL 或 PostgreSQL，但更换连接信息不会自动搬迁数据，还需检查类型、默认值、约束及目标数据库测试结果。
