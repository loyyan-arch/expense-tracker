## 2. 先区分三种持久化

1. 数据持久化：账单写入 SQLite，服务器通过命名数据卷保留数据库。程序退出不等于账单丢失；命名卷被删除、挂载错误或服务器故障是另一类问题。
2. 登录状态保持：刷新页面后恢复身份，当前尚未实现。需要有期限的会话设计、退出撤销和启动恢复状态，不能只在前端记住一个用户名就算登录。
3. 页面状态保持：月份、分类、页码等查询状态放进 URL，刷新和浏览器后退后仍可恢复。它不等于保存账单或保存密码。

补一轮数据持久化验收即可，不重新写数据库：记录测试账号及账单 → 核对实际挂载卷 → 重启后端 → 保留同一卷重建后端 → 重启 Nginx 解析新的后端地址 → 核对账号、账单与统计。执行前保留已有有效副本，不使用 down -v。换一个空数据卷不属于持久化成功。

参考：[Docker 数据卷生命周期](https://docs.docker.com/engine/storage/volumes/)。

## 3. 按完整功能推进的主线

每个功能都按“确定规则 → 后端与测试 → 前端交互 → 联调验收 → Git/发布记录”完成，避免把每个小函数拆成一课。年度总览已交付，其余是待开发建议；下一课从功能二开始。

### 功能一：年度收支总览（已完成，PR #8）

目标：选择一个年份，看到全年收入、支出、结余和 12 个月的明细。

1. 定义口径：按 occurred_on 归属自然年，按当前用户隔离，金额仍为整数分；全年汇总不受账单列表分类和分页影响。
2. 新增 GET /statistics/yearly?year=2026，限制年份 1～9998；范围为当年 1 月 1 日含、次年 1 月 1 日不含。
3. 在数据库按月份和收支类型聚合；应用补齐无记录月份为零，不加载全部账单再在浏览器求和。
4. 返回全年总额和按 1～12 月排序的固定 12 项明细；现有月度接口继续保留。
5. 前端增加年度选择、汇总卡片和月度表格；图表可在数据口径通过后再加。
6. 验证空年、只有收入/支出、负结余、跨年边界、闰日、用户隔离、快速切年；全年总额等于 12 个月汇总。

已有日期与金额字段足够，一般不需要数据库迁移。改账单日期跨年后，两年的统计都应正确。

### 功能二：刷新后保持登录

目标：有效会话内刷新页面无需重输密码；过期或退出后确实失效。

1. 明确浏览器重启是否仍保持登录、会话有效期和退出范围；保留用户已决定的注册密码 7～128 位规则。
2. 设计服务端可撤销会话与 HttpOnly Cookie，或短期访问令牌搭配可撤销刷新会话；选定一种后实现，不叠加两套。
3. 如采用会话表，用 Alembic 增加迁移，完成创建、到期检查、注销和清理。
4. 前端增加“正在恢复登录状态”，应用初始化查询身份后再决定路由；401、网络故障分别处理，避免刷新时误跳登录页。
5. 覆盖 cookie 认证的 CSRF 防护、SameSite、生产 Secure 配置；开发 HTTP 与生产 HTTPS 配置分开。备案等待期间可以完成本地或隧道验证，生产安全配置留到公网验收。
6. 验证刷新、过期、退出、旧凭证重用、多标签页与双账号状态隔离。

不把长期 Token 简单放入 localStorage 作为完整方案；HttpOnly 降低脚本直接读取凭证的风险，但不能替代 XSS/CSRF 防护。参考：[OWASP 浏览器存储建议](https://cheatsheetseries.owasp.org/cheatsheets/HTML5_Security_Cheat_Sheet.html#local-storage)。

### 功能三：完整的账单查询

目标：按起止日期、收入/支出、分类和备注关键词找到记录；刷新后保留筛选。

1. 明确日期范围与原 month 参数的关系，避免两个条件隐式冲突；列表展示筛选口径。
2. 后端增加日期、kind、关键词及明确的排序参数，输入校验与用户条件始终保留。
3. 需要总条数时新增带 items/total 的响应设计，同步前端及测试；不能直接改现有数组而不处理兼容。
4. 将筛选条件与页码写入 URL，校验 URL 参数；筛选变化回第一页。
5. 如按发生日期排序，使用日期和 ID 组成稳定排序，避免同日记录顺序漂移。
6. 验收跨月范围、空结果、关键词、翻页、返回页面及快速切换旧响应问题。

### 功能四：分类分析与趋势展示

目标：回答“这个月钱花在哪、全年哪几个月支出最多”。

1. 后端按所选期间、当前用户、收支类型聚合分类金额。
2. 先用表格展示各分类金额，再增加简单条形图或趋势图；图表与表格使用同一份数据。
3. 明确占比分母，收入和支出分开，分母为零显示无数据；不能将收入和支出混为同一个饼图。
4. 验证分类合计与对应期间总额相等；分类筛选后的列表和全量统计分别标明范围。

### 功能五：账号管理与会话保护

目标：用户可以修改密码，并使旧会话失效。

1. 输入旧密码、新密码及确认值；后端校验旧密码并重新哈希。
2. 基于功能二的会话机制实现改密后撤销会话，重新登录；不仅清除当前页面 Token。
3. 前端增加账号设置页，处理错误、重复提交和成功后跳转。
4. 验证旧密码不可登录、新密码可用、旧会话不可再访问账单。

忘记密码单独作为后续功能：先确定已验证的邮箱等身份恢复渠道，再做一次性、限时、不可复用的恢复凭证；不能只凭用户名重置。

### 功能六：用户导出自己的账单

目标：按所选范围导出 CSV，可用 Excel 打开。

1. 后端沿用查询过滤和用户隔离；导出全部匹配记录而不是当前 10 条。
2. 明确列名、日期与金额格式、中文编码，并处理备注中的逗号、换行和电子表格公式风险。
3. 前端提供导出按钮、加载反馈与文件名。
4. 验证跨页、空记录、中文备注和双账号隔离。

导出是用户功能，不等于数据库备份。导入 CSV 暂不与导出一起做，后续需解决预览校验、重复导入和失败回滚。

### 功能七：小范围试用与受控发布

目标：能更新应用、发现故障，知道真实负载边界。

1. 完成新界面分支收尾，区分源码提交、前后端镜像标签、实际镜像 ID 与数据库迁移版本。
2. 先记录持久化验收，再用新版本镜像更新与回退验证；不覆盖旧 1.0.0。
3. 验证代理真实 IP、可信代理边界和登录限流；确定公开注册或邀请试用策略，再考虑注册限流。
4. 检查磁盘、容器内存、日志轮转、健康状态；在测试环境用代表性查询测量响应和数据库写入冲突。
5. 对慢查询先看查询计划和数据量，再决定是否加用户+日期等索引。是否换数据库或扩容由测量决定。

域名未通过时可以继续 SSH 隧道验收，公网验收另行完成。不需要先引入网关、Redis、消息队列、微服务或 Kubernetes。

## 4. 主线后再选的扩展

- 自定义分类：新增用户分类表与迁移；决定分类重命名、归档/删除后历史账单如何保留。现有固定分类够用时不急于改模型。
- 月预算：总预算、实际支出、剩余额度、超支提示；先站内展示，不同时接短信或邮件。
- 账单导入：解析预览、逐行校验、重复识别与事务策略。
- 多账户、转账、退款：需要重新确认统计口径，不能将转账简单算作收入或支出。
- 自动备份与异地恢复：用户当前明确暂缓。已有方案保留但不继续安装定时任务，不把持久化误当备份。

这些扩展不是首版试用的全部前置条件。优先完成年度统计和登录体验，再根据试用反馈选取。
