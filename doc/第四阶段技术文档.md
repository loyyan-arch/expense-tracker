# 个人记账后端：第四阶段技术文档

阶段目标：注册、登录、识别当前用户，建立账单归属，并防止跨账号访问数据。

阶段状态：已完成。依据包括当前代码核对、学习者手工反馈，以及学习者提供的 pytest 结果：3 passed, 1 warning in 1.08s。本次文档整理未重新执行测试。自动化覆盖范围见文末，不能将三个测试理解为所有安全场景都已验证。

## 1. 用户注册与密码

新增 users 表：id、username、password_hash、created_at。username 有数据库唯一约束，密码使用 pwdlib 的 Argon2 支持进行哈希，数据库不保存明文。

`POST /auth/register` 接收用户名和密码，成功返回 201 和 UserPublic（id、username）；重复用户名返回 409；输入校验失败返回 422。当前实际 UserCreate 密码长度为 7～128，用户名为 3～32 位小写字母、数字或下划线；这与教学最初给出的最小密码长度 15 不同，后续上线前应统一密码策略与测试。

IntegrityError 发生后先 rollback，再判断是否为用户名冲突，其他错误继续抛出。响应不包含密码或密码哈希。应用引擎配置 echo=False、hide_parameters=True，避免 SQL 参数直接输出。

## 2. 登录与 token

`POST /auth/login` 使用 JSON 请求体。正确凭证返回 200、access_token 和 token_type=bearer；错误凭证返回统一的 401；缺少密码字段返回 422。

verify_password 验证输入密码与数据库哈希。用户名不存在时使用预生成的占位哈希进行验证，减少快速返回带来的时间差。

JWT 使用 HS256 签名，密钥从 JWT_SECRET 环境变量读取。当前有效期为 30 分钟，包含 sub（字符串用户 ID）、iat（签发时间）和 exp（过期时间）。签名不是加密，token 不保存密码。

PowerShell 环境变量设置只对当前终端及其子进程有效；重新生成密钥会使旧 token 签名验证失败。登录接口不修改数据库，因此无需 commit。

## 3. 当前用户与身份认证

请求头格式：`Authorization: Bearer <token>`。

`get_current_user` 通过 HTTPBearer 读取凭证，然后调用 decode_access_token：固定允许的算法、验证签名和有效期、要求 sub/iat/exp 存在、检查用户 ID 格式及范围。随后查询用户是否仍存在。

缺失、无效或过期凭证，以及不存在的用户，返回 401。`GET /auth/me` 通过 Depends(get_current_user) 获取 UserPublic 并返回。

在 /docs 中调用登录接口，不会自动替换 Authorize 保存的 token。需要手动粘贴新 token，再通过 /auth/me 确认身份。Logout 只是让文档页面停止发送 token，不是服务端撤销凭证；当前没有撤销列表或刷新 token 功能。

## 4. 数据库迁移与已有账单

使用 Alembic 管理结构变更。env.py 读取应用引擎地址及 Base.metadata，导入全部模型。

- 0001：记录原始 users、transactions 两张表。已有数据库核对结构后使用 stamp 0001，仅记录版本。
- 0002：添加 transactions.user_id，回填已有账单，再设为非空，添加命名外键和索引。

基线已由带教在独立临时空数据库执行 upgrade 0001 和 check 验证。0002 由学习者执行并反馈版本、结构和归属统计符合预期。

旧账单归属经学习者明确指定为 loyyan，迁移前核对其 ID 为 1、原有账单 13 笔。命令：

```powershell
python -m alembic -x legacy_owner=loyyan upgrade head
```

迁移脚本先检查旧数据及目标用户，再添加可空列、回填 user_id，最后用 batch_alter_table 建立最终约束。空数据库没有旧账单时无需预先存在 loyyan。SQLite 的批量变更会在必要时重建表并复制数据。

当前版本 0002。backup_db.py 通过 SQLite backup API 生成备份并检查文件完整性；verify_ownership.py 汇总归属并执行 foreign_key_check。备份完整性检查不等于恢复演练。

## 5. 数据归属与权限

应用引擎通过 connect 事件执行 PRAGMA foreign_keys=ON。此监听器绑定应用 engine；Alembic 自行创建的引擎和独立 sqlite3 连接不会自动继承它。

外键保障用户引用有效，业务条件保障当前用户有权访问，两者不可互相替代。

| 接口 | 权限实现 |
| --- | --- |
| POST /transactions | user_id 从 current_user.id 取得 |
| GET /transactions/{id} | 同时匹配账单 ID 与当前用户 ID |
| PATCH /transactions/{id} | 在当前用户范围中找到记录再修改 |
| DELETE /transactions/{id} | 在当前用户范围中找到记录再删除 |
| GET /transactions | 先按用户筛选，再进行其他筛选及分页 |
| GET /statistics/monthly | 按用户和月份筛选后分组求和 |

所有上述接口使用 Depends(get_current_user)。对其他用户的账单统一返回 404，避免通过差异响应暴露其是否存在。

TransactionCreate 和 TransactionUpdate 均设置 extra="forbid"，没有可由客户端填写的 user_id；额外提交此字段会返回 422。

## 6. 自动化测试

tests/conftest.py 创建测试进程专用随机 JWT 密钥，通过 tmp_path 为每个测试创建独立 SQLite 文件，并使用 monkeypatch 将 main.engine 替换为测试引擎。测试引擎同样开启外键检查。

TestClient 在进程内调用应用，不需要启动 Uvicorn。测试用户和账单都位于临时数据库，不使用现有 loyyan 数据。create_all 只用于创建测试表，本组测试不验证 Alembic 迁移。

学习者执行：

```powershell
python -m pytest tests/test_permissions.py -v
```

已通过的三个测试：

| 测试 | 覆盖行为 |
| --- | --- |
| test_other_user_cannot_access_bill | B 无法查询、修改、删除 A 的账单，A 数据保持不变 |
| test_list_and_statistics_are_isolated | A/B 列表和同月统计分别只包含自己的账单 |
| test_client_cannot_set_owner | 伪造 user_id 返回 422，且未产生账单 |

测试输出为 3 passed, 1 warning。已核对本机 Starlette TestClient 源码：优先使用 httpx2，缺失时兼容回退 httpx 并发出弃用警告。因此警告不表示权限测试失败，安装 httpx2 后可随新增测试一起复验。本次整理尚未安装该依赖。

待补充的自动化场景包括：各接口未登录、格式非法/过期/错误签名 token、普通业务输入、迁移与备份恢复。这些属于第五阶段后续工作。

## 7. 排障记录

曾出现服务显示启动完成但浏览器一直等待。实际检查首页、/docs、/openapi.json 均超时，发现旧 Python 进程与新重载进程同时监听 8000 端口。停止已确认的旧进程后，三个地址均返回 200。

结论：当时问题来自残留进程，不能仅根据最近新增的哈希代码推断启动慢。重启时应在服务终端 Ctrl+C 并等待退出；排查时分别检查首页、文档 HTML、接口描述响应。
