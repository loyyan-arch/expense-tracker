## 2. 代码结构与职责

| 文件 | 职责 |
| --- | --- |
| main.py | 创建应用、设置日志、注册中间件和路由 |
| schemas.py | 请求字段约束、响应字段定义 |
| models.py | SQLAlchemy 表模型及约束 |
| db.py | 创建引擎、开启外键检查、提供 get_db |
| dependencies.py | 读取 Bearer 凭证、验证 Token、查询当前用户 |
| security.py | 密码哈希、密码验证、JWT 签发与解码 |
| config.py | 集中读取与校验配置 |
| routers/auth.py | 注册、登录、当前用户接口 |
| routers/transactions.py | 账单增删改查与筛选分页 |
| routers/statistics.py | 月度收支统计 |
| request_logging.py | 请求编号、状态码、处理耗时及异常堆栈 |

`get_db()` 通过 yield 提供 Session，并在请求依赖结束后关闭。路由及认证通过 `Depends(get_db)` 获取会话；默认依赖缓存允许同一请求复用该依赖结果。写操作仍由业务代码显式 commit，需要处理的数据库异常显式 rollback；关闭会话不等于提交。

`get_current_user()` 返回 UserPublic，不向业务层传递密码哈希。各账单操作仍在查询条件中限制当前用户，模块拆分不会替代权限检查。

## 3. 请求与响应模型

TransactionCreate、TransactionUpdate 继续校验类型、金额、日期和分类，并使用 `extra="forbid"` 拒绝客户端指定 user_id 等额外字段。更新使用 `exclude_unset=True` 区分未提交字段；空修改和显式 null 由接口处理。

TransactionPublic 使用 `ConfigDict(from_attributes=True)`，允许从 ORM 对象读取响应字段。账单创建、单条查询、修改与列表通过 response_model 定义输出；不返回 user_id。删除保持 204 无响应体。月份统计目前仍直接返回统计字典。

## 4. 配置管理

Settings 使用 pydantic-settings，从系统环境变量、项目根目录 `.env` 和默认值读取配置，优先级依次降低。

| 配置 | 当前约束 |
| --- | --- |
| JWT_SECRET | SecretStr，至少 32 个字符，无默认值 |
| ACCESS_TOKEN_EXPIRE_MINUTES | 默认 30，范围 1～1440 |
| DATABASE_PATH | 默认项目根目录 expenses.db，相对路径以项目根目录为基准 |

配置使用 `extra="forbid"`、`hide_input_in_errors=True`。SecretStr 减少普通展示时的泄露，但不能替代对日志内容的控制。签名时通过 get_secret_value 取得真实密钥。签名算法仍固定为 HS256。

应用数据库路径统一来自 settings；Alembic、备份与归属检查沿用该路径。切换 DATABASE_PATH 后应在同一终端运行相应命令，并在演练后清除临时覆盖。修改 `.env` 后手动重启服务。保持密钥不变时，重启本身不会撤销未过期 Token；更换密钥后旧签名失效。

仅提交 `.env.example`；真实 `.env`、数据库、备份和虚拟环境均被 Git 忽略。

## 5. 请求日志与错误处理

中间件为每次请求生成 UUID 编号，保存到 request.state.request_id，使用 perf_counter 计算处理耗时。正常返回的响应记录方法、路径、状态码和耗时，并添加 X-Request-ID 响应头。401、404、422 等由框架处理的 HTTP 错误也走该流程。

未处理异常通过 logger.exception 记录堆栈后重新抛出。当前未处理的 500 不保证带 X-Request-ID 响应头；没有实现统一业务错误码或自定义全局异常响应。

耗时是到 call_next 返回响应的时间，不是完整网络传输时间。日志不主动记录请求体、Authorization、密码或 Token；异常堆栈仍需避免夹带业务敏感信息。

按学习者决定，目前仅输出终端，未设置文件保存、轮转或集中收集。Uvicorn 自身日志另有配置，上线时需确认运行环境的收集与保留策略。

## 6. 自动化测试

测试使用 TestClient，无须启动 Uvicorn。conftest 在导入应用前设置随机测试 JWT 密钥，为每个测试创建临时 SQLite 数据库，并开启外键检查。通过 `app.dependency_overrides[get_db]` 替换数据库会话依赖，结束后移除覆盖并释放引擎。

这取代了第四阶段文档中的 monkeypatch main.engine 方式。测试建表使用 Base.metadata.create_all，不验证迁移脚本。

| 用例组 | 参数化后数量 | 验证内容 |
| --- | --- | --- |
| 未登录访问 | 7 | 当前用户、账单操作及月度统计返回 401 |
| 无效凭证格式 | 2 | 非法 Bearer Token 与错误认证类型被拒绝 |
| 无效签名或过期 | 2 | 真实用户的错误密钥签名、过期 Token 返回 401 |
| 跨用户单条操作 | 1 | B 查询、修改、删除 A 账单均失败，A 数据未变化 |
| 列表与统计隔离 | 1 | 两个用户仅看到各自列表与统计 |
| 伪造归属 | 1 | 提交 user_id 返回 422，未产生记录 |

总计 14 个用例。注册、登录、创建账单也作为测试准备步骤执行，但未完整覆盖这些功能的失败路径。正常修改、正常删除、金额/日期/分页边界、重复注册等仍需进一步补充自动化断言。迁移和备份恢复目前采用独立的手工演练。

## 8. 备份恢复演练

backup_db.py 使用只读源连接及 SQLite backup API 生成时间戳备份，执行 integrity_check。verify_ownership.py 汇总账单归属并执行 foreign_key_check。

本次教学演练流程如下，学习者反馈整体通过：

1. 记录原账单及月份统计，停止继续写入，生成备份。
2. 将已关闭的备份复制到独立 restore_check.db，禁止覆盖已有目标。
3. 临时设置 DATABASE_PATH 指向恢复库，检查迁移版本、模型差异和外键归属。
4. 在独立端口启动服务，使用原账号登录，核对账单及统计。
5. 新增并删除演练账单，验证恢复后可继续读写。
6. 停止服务，清除临时配置覆盖。

本次整理未找到单独的演练记录文件，也没有重新操作日常数据库；不补造备份文件名或耗时。今后演练应记录文件名、备份时间、恢复耗时及逐项结果。本地恢复成功不等于已配置生产定期备份或异地保存。
