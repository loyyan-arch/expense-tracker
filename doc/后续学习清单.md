本清单安排学习顺序；《项目分阶段开发清单》记录实际交付状态。每课按“理解原因 → 自己实现 → 验收 → 必要时 PR 合并”推进，不以复制代码或看到容器 Up 作为全部验收。

## 2. 接下来逐课推进

### 第 1 课：登录限流（下一课）

- [ ] 理解连续登录尝试的影响，以及 401 和 429 的区别。
- [ ] 选择并实现计数规则、窗口/过期时间和响应行为，考虑账号与来源地址。
- [ ] 说明计数存储在进程内与共享存储中的差异，明确当前单实例适用范围。
- [ ] 理解反向代理下真实来源地址的取得与信任范围，避免随意信任请求头。
- [ ] 添加阈值内、超限、窗口恢复等可重复测试。

产出：实现、测试、PR 和配置说明。验收：正常登录可用，连续尝试按规则返回 429，过期后恢复，不依赖长时间 sleep 才能测试。

### 第 2 课：认证策略与业务边界测试

- [ ] 复核当前最短 7 位密码策略；明确新注册策略和已有账号兼容方式。
- [ ] 验证重复注册、错误密码、无效和过期 Token 等行为。
- [ ] 补充 PATCH 空对象、null、非法金额，并确认失败时原记录不变。
- [ ] 补充分页边界、月份首尾、跨年与无账单月份测试。
- [ ] 复核错误响应不泄露密码或内部配置，更新 README 测试说明。

产出：认证规则说明和业务回归测试。验收：本地与 CI 通过，能解释每条测试防止什么问题，不追求单纯增加测试数量。

### 第 3 课：补做容器独立恢复（此前暂缓）

- [ ] 检查 Windows 上导出的备份文件。
- [ ] 使用独立 Compose 项目、数据卷和端口恢复服务。
- [ ] 验证原账号登录、账单、统计与恢复后的新增/删除。
- [ ] 确认恢复环境的写入不影响原服务，记录备份时间点和恢复耗时。

产出：恢复配置及演练记录。验收：脱离原数据卷仍能运行。此前本地恢复已完成，本课仍待做；可安排在服务器采购期间，但不跳过上线前的数据恢复验证。

### 第 4 课：明确购买需求与部署方案（可与前几课并行）

- [ ] 确定预算、主要访问地区、使用人数、是否开放注册、可接受中断时间。
- [ ] 按当前产品与价格比较服务器、续费、带宽/流量、磁盘和备份成本。
- [ ] 选择 Linux 系统与 CPU 架构，确认镜像和依赖兼容。
- [ ] 确定域名方案，按实际地区和服务商核对适用要求。
- [ ] 确定首次上线使用空库还是保留练习账单。

产出：简短部署方案和采购清单。验收：能解释所选资源如何满足需求及费用构成，再执行购买。不在需求未明确时预先固定厂商或套餐。

### 第 5 课：Linux 与服务器初始化

- [ ] 通过 SSH 密钥连接服务器，建立日常管理用户。
- [ ] 学习目录、权限、进程、端口、磁盘和系统服务的常用排查命令。
- [ ] 配置安全组和防火墙；理解管理端口、网站入口与容器内部端口。
- [ ] 安装 Docker/Compose，验证服务启动和系统重启后的运行情况。

产出：服务器初始化记录。验收：能可靠登录，Docker 可用，明确公网开放的端口及其用途。

### 第 6 课：把项目部署到服务器

- [ ] 选择镜像交付方式，并将版本对应到 Git 提交。
- [ ] 配置服务器专用环境变量与密钥，不复用公开的 CI 占位密钥。
- [ ] 创建持久化存储并验证普通应用用户的访问权限。
- [ ] 执行迁移或已确认的数据恢复流程。
- [ ] 验证健康检查、日志、登录、账单读写、统计与重建后数据保留。

产出：服务器部署配置与启动说明。验收：服务在服务器上运行，数据路径明确；此时尚不能据此宣布 HTTPS 和公网验收完成。

### 第 7 课：域名、反向代理与 HTTPS

- [ ] 理解 DNS、端口、反向代理和 TLS 各自负责什么。
- [ ] 选择并配置反向代理，将请求转发到应用。
- [ ] 配置域名解析、证书、HTTPS 与续期安排。
- [ ] 明确代理头信任范围及 /docs 等入口的公开策略。
- [ ] 使用外部网络测试 HTTPS、认证、权限与限流。

产出：域名与代理配置说明。验收：目标域名证书有效，公网接口行为符合预期，后台内部端口无须直接暴露。

### 第 8 课：生产备份与基础监控

- [ ] 自动执行数据库备份，配置保留周期及异地副本。
- [ ] 验证备份失败能被发现，而非只确认定时任务“存在”。
- [ ] 从服务器备份恢复到隔离环境，记录可恢复的数据时间点和所需时间。
- [ ] 检查可用性、磁盘容量、错误日志和通知路径。

产出：备份计划、恢复记录与基础监控。验收：能用备份恢复业务，能发现模拟的备份或可用性故障。数据卷、同盘副本和健康状态各有边界，不能相互替代。

### 第 9 课：服务器发布与回退

- [ ] 保存发布前版本信息和必要备份。
- [ ] 发布指定镜像版本，验证健康及关键业务。
- [ ] 完成一次受控回退，说明代码与数据库结构的兼容条件。
- [ ] 记录发布失败、迁移失败与数据恢复的处理步骤。

产出：可执行的发布/回退手册。验收：能按记录重复操作；不把代码回退误认为数据恢复，也不宣称当前单容器发布零停机。

### 第 10 课：首版上线验收与阶段总结

- [ ] 在公网完成两个账号的业务及权限验收。
- [ ] 复核服务器重启恢复、证书、备份、日志与版本信息。
- [ ] 完成第六阶段技术文档，更新 README 和开发清单。
- [ ] 通过 PR 保存上线版本检查点，并记录仍存在的限制。

产出：上线验收记录和版本检查点。完成标准：公网 HTTPS 可用，关键业务正确，备份经过恢复验证，发布和故障处理有记录。

## 3. 首版上线后再学习

以下是扩展方向，不是这次上线的必做前置条件。

| 顺序 | 主题 | 练习与验收 |
| --- | --- | --- |
| 1 | 简单前端接入 | 完成登录、授权、账单分页、错误展示，按实际来源配置 CORS |
| 2 | 数据库进阶 | 理解事务、索引与查询计划，基于测量处理慢查询；按需求演练 PostgreSQL/MySQL 迁移 |
| 3 | 业务扩展 | 从分类管理、导出、预算中选一项，完成需求、接口、测试和发布 |
| 4 | 性能与异步任务 | 出现耗时任务或瓶颈后再引入队列/缓存，验证必要性与收益 |
| 5 | 更完整的认证与交付 | 按客户端需求学习 Token 刷新/撤销，再考虑自动镜像发布与受控部署 |

暂不把微服务、Kubernetes、消息队列或数据库替换设为学习门槛。先完整交付并维护这一个项目。

## 4. 每课固定节奏

1. 先说明问题、当前实现的边界和本课改动范围。
2. 需要改代码时，从同步后的 dev 创建短期分支。
3. 学习者实现，执行与改动匹配的测试或部署演练。
4. 提交 PR，检查差异及 CI，合并并同步本地。
5. 记录实际验收结果与剩余事项；配置了但没验证的项目不勾选完成。

服务器上的配置操作同样记录步骤，但密钥、Token、数据库和备份不提交到仓库。源代码、镜像、运行配置和数据库分别管理。
