## 2. 接下来逐课推进

### 第 1 课：登录限流（基础版完成，PR #3 已合入）

- [x] 理解连续登录尝试的影响，以及 401 和 429 的区别。
- [x] 实现按来源 IP 的固定窗口计数：从首次请求起 60 秒内最多允许 5 次登录尝试；超限返回 429 和 Retry-After。
- [x] 使用进程内存、线程锁和过期记录清理；明确重启清空、多进程不共享、共用 IP 共享额度的边界。
- [x] 添加阈值内、超限、来源隔离、窗口恢复、等待时间、并发计数和接口测试。
- [ ] 在第 7 课配置可信代理并实际验证来源 IP；账号维度限制暂未实现。

产出：实现、测试、PR 和配置说明。验收：正常登录可用，连续尝试按规则返回 429，过期后恢复，不依赖长时间 sleep 才能测试。

### 第 2 课：认证策略与业务边界测试（本地完成，PR #4 已合入）

- [x] 按学习者决定保留注册密码 7～128 个字符、登录输入 1～128 个字符；验证注册长度 6、7、128、129 的边界及合法边界登录。
- [x] 验证重复注册返回 409 且原账号不被覆盖，复用已有无效和过期 Token 测试。
- [x] 登录用户名不存在时返回 401“用户名不存在，请先注册”；密码错误时返回 401“密码错误”。明确区分账号存在与否是当前产品选择。
- [x] 验证 PATCH 空对象、金额 null、非法金额、合法与非法字段混合、伪造归属均被拒绝，原账单不变。
- [x] 验证分页顺序、越界和非法参数，以及月份首尾、跨年、闰年和无账单月份的列表与统计。
- [x] 请求校验错误仅返回 loc、msg、type；验证三种密码校验失败场景不回显原始 input，更新 README。此项不代表所有响应和日志的敏感信息场景均已验证。

产出：认证规则说明、校验错误处理和业务回归测试。当前本地 58 个测试通过，PR #4 已合入；本次整理未独立核对该 PR 的 CI 结果。测试验收以具体行为为准，不追求单纯增加数量。

### 第 3 课：独立容器备份恢复（暂缓，恢复验收移至第 8 课）

- [ ] 检查 Windows 上导出的备份文件。
- [ ] 使用独立 Compose 项目、数据卷和端口恢复服务。
- [ ] 验证原账号登录、账单、统计与恢复后的新增/删除。
- [ ] 确认恢复环境的写入不影响原服务，记录备份时间点和恢复耗时。

本地恢复和容器备份导出此前已完成；Windows 备份导入独立数据卷的练习按学习者决定暂缓，不作为开始服务器部署的前置条件，也不勾选完成。第 8 课直接使用服务器备份，在隔离环境完成恢复和业务验证。

本课完整步骤：盘点原服务和备份 → 校验备份 → 创建独立 Compose 项目、空数据卷及未占用端口 → 导入备份并检查权限 → 启动与业务验收 → 验证两套服务互不影响 → 记录恢复点、耗时及操作命令。不要直接覆盖或删除原数据卷；不要把备份、密码和密钥提交到 Git。

## 4. 每课固定节奏

1. 先说明问题、当前实现的边界和本课改动范围。
2. 需要改代码时，从同步后的 dev 创建短期分支。
3. 学习者实现，执行与改动匹配的测试或部署演练。
4. 提交 PR，检查差异及 CI，合并并同步本地。
5. 记录实际验收结果与剩余事项；配置了但没验证的项目不勾选完成。

服务器上的配置操作同样记录步骤，但密钥、Token、数据库和备份不提交到仓库。源代码、镜像、运行配置和数据库分别管理。
